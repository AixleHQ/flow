# UX Audit — Full Application Sweep

**Date:** 2026-08-02
**Auditor:** Freya (WDS Designer)
**Scope:** every Inertia page rendered by `app/controllers/**` (38 screens) + `AuthLayout`,
`AppSidebar`, `PageShell`, the shared `resources/*` content components, and the theme contract
in `shared/theme/mantineTheme.ts`.
**Method:** source read of all page components and their CSS. No runtime/browser pass —
findings are structural, not pixel measurements.

---

## Executive summary

The product has a real design system underneath it — a semantic `--app-*` token contract,
a tuned Mantine theme, an Aixle type ramp — and roughly half the screens honour it. The other
half were built past it. The result is not an ugly app; it is an app that reads as **four
products stitched together**: the Mantine-native resource screens, the hand-CSS Workflows/Builder
surface, the inline-`CSSProperties` Overview/Analytics surface, and the Docs surface with its own
1181-line stylesheet.

The three changes with the highest leverage, in order:

1. **A `PageHeader` component + a `StatusBadge` primitive.** Five different H1 treatments and six
   independently-defined `STATE_CONFIG` maps are the single biggest source of "this feels
   unfinished". Both are ~100 lines of work and touch every screen.
2. **One confirmation mechanism.** Three exist today, and the weakest one (native `confirm()`)
   guards the *highest*-consequence action in the app: deleting a secret.
3. **Decide whether this app is responsive.** Eleven `@media` rules exist in the entire frontend,
   five of which are `prefers-reduced-motion` or the Docs page. The sidebar has a mobile drawer,
   which promises a mobile experience the page bodies do not deliver. Either finish it or drop the
   drawer and state a minimum width.

Everything below is evidence-backed with `file:line`.

## 1. Systemic findings

### 1.1 Four competing styling systems

| System | Where | Example |
| --- | --- | --- |
| Mantine props | Most resource screens | `shared/resources/agents/AgentsContent.tsx` |
| CSS modules | Login, Settings, Profile, Docs, Sidebar | `pages/Projects/Settings/SettingsPage.module.css` |
| Inline `CSSProperties` map | Overview | `pages/Projects/Overview/OverviewPage.tsx:94-245` |
| Raw `<style>` + hand class names | Workflows | `pages/Projects/Workflows/WorkflowsPage.tsx:206-234` |

Counts: **183** inline `style={{}}` objects in `BoardPage.tsx` alone, **60** in `TriggerFormPanel.tsx`,
**152** hardcoded 6-digit hex literals across `pages/` + `shared/` TSX — in a codebase that
documents `--app-*` as "the app's theming contract" (`mantineTheme.ts:89-96`).

**Change:** freeze the contract. Mantine props for layout/spacing, CSS modules for anything
structural, `--app-*` for every colour. Add a lint rule banning hex literals in `.tsx` under
`pages/` and `shared/`, with the existing frozen-allowlist pattern already used for the
`Testing/*` cops.

### 1.2 The sidebar AI banner is dark-mode-only

`AppSidebar.tsx:247-359` is fully inline-styled with `#cf6b4a`, `#d1cfcd`, `#0a0908` and a
JS hover handler swapping `#d1cfcd` ↔ `#e3e1df`. In light theme this renders a **light-grey
button with near-black text on a white sidebar** — the primary CTA of the whole navigation is
the lowest-contrast element on the screen. The same file also hardcodes `color: '#cf6b4a'` for
the collapsed icon.

**Change:** rebuild as a CSS module using `--app-primary` / `--app-bg-paper` / `--app-text-primary`.
This is the most visible single defect found.

### 1.3 No page-header component — five H1 treatments

| Treatment | Screens |
| --- | --- |
| `fz={32} fw={600}` | Projects index, Workflow Catalog, Profile |
| `fz={24} fw={600}` | Agents, Tools, Skills, MCP servers, Assets |
| `Title order={2}` | Members (company + project), Repositories, Integrations, Config items |
| `size="xl" fw={700}` | Project Analytics, Company Analytics, Usage, Board, Builder landing, Onboarding |
| inline `fontSize: 24` / `fontSize: 18` | Overview (`:99`), Workflows (`:240`), Builder (`:549`) |

Same semantic rank, five sizes, three font weights, two colour sources.

**Change:** one `PageHeader({ title, subtitle, actions, breadcrumbs })`. Migrate all 38 screens.
This alone resolves ~40% of the "different products" impression.

### 1.4 Seven screens have no browser title

Missing `<Head title>`: `Projects/IndexPage`, `Profile/Show`, `Company/Sessions/{Index,Show,Artifacts}`,
`Company/Members/Index`, `Company/Assets/Index`. Tabs, history and bookmarks are unusable on these.

**Change:** fold `<Head>` into `PageHeader` so it cannot be forgotten.

### 1.5 No breadcrumbs anywhere in the app

`grep Breadcrumb` returns hits only in `pages/Docs/`. The deepest routes —
project → workflow → builder → step editor, and project → run → step run → terminal — offer
a single back-arrow at best. The workspace switcher tells you which project you are in; nothing
tells you where you are inside it.

**Change:** breadcrumbs in `PageHeader`, derived from the route. The Docs surface already proves
the pattern works here (`pages/Docs/components/DocsBreadcrumb.tsx`).

### 1.6 Responsiveness is promised but not delivered

Eleven `@media` rules total (`PageShell`, `LoginPage`, `SettingsPage`, `Profile/Show`, `DocsPage` ×3,
plus 4 `prefers-reduced-motion`). Meanwhile:

- `AppSidebar.tsx:764` renders a full mobile drawer below 768px — promising a mobile app.
- Workflows grid is fixed `repeat(2, 1fr)` (`WorkflowsPage.tsx:342`).
- Overview is fixed `1fr 1fr` (`OverviewPage.tsx:146`).
- Analytics "Workflow Breakdown" is a hand-rolled grid at
  `1fr 120px 100px 100px 100px 80px 90px 90px` (`Analytics/AnalyticsPage.tsx:752`) — clips below ~1400px.
- Only two tables use `Table.ScrollContainer`; the rest overflow the viewport.

**Change:** pick one. Either (a) add a `--content-min` and `Table.ScrollContainer` everywhere,
make the fixed grids `auto-fit`, and keep the drawer; or (b) remove the drawer, state a 1024px
minimum, and stop paying for half a mobile experience.

### 1.7 Three confirmation mechanisms — the weakest guards secrets

| Mechanism | Used by |
| --- | --- |
| `modals.openConfirmModal` | Settings archive/delete, Repositories, Integrations, Assets |
| Custom `<Modal>` | Workflows delete, Profile "leave company" |
| Native `confirm()` | `MembersContent.tsx:140`, `ConfigItemsContent.tsx:63`, `BoardPage.tsx:4385`, `MembersPage.tsx:77`, `Profile/Show.tsx:849` |

Native `confirm()` is unstyled, un-brandable, thread-blocking, and suppressible by the browser
("don't let this page create more dialogs"). Deleting a **secret** — the single most destructive
action in the product — uses it.

**Change:** one `useConfirm()` wrapping `modals.openConfirmModal`; delete all five native calls.
For secrets specifically, escalate to type-the-name confirmation.

### 1.8 Status vocabulary is redefined six times

`STATE_CONFIG` / `STATE_COLORS` is independently declared in `Projects/Sessions/SessionsPage.tsx:51`,
`Company/Sessions/Index.tsx:56`, `WorkflowRuns/WorkflowRunsPage.tsx:30`,
`WorkflowRuns/ShowPage.tsx:119`, `Board/BoardPage.tsx:271`, `AixleBuilder/LandingPage.tsx:70`.
They disagree: `running` renders as **"Starting"** in the sessions list and **"Running"** in the
runs list. `ready` renders as "Running" in sessions and does not exist in runs.

**Change:** one `shared/ui/StatusBadge` with a single state→(label, tone) table, keyed by domain.

### 1.9 Charts use a Material palette, not the Aixle palette

`#2196f3 #9c27b0 #4caf50 #ff9800 #00bcd4 #f44336 #795548` appear in Project Analytics, Company
Analytics, Usage, Overview activity dots and Board stats. These are Material Design defaults —
they belong to a different product than the terracotta/warm-black shell around them.

**Change:** derive a categorical ramp from the brand tuple + neutrals. Chart colour is the loudest
brand signal on any analytics screen and currently says "generic dashboard".

### 1.10 Empty states use two different vocabularies

Emoji-as-icon: `🔧` (Tools `:163` **and** Skills `:130` — same glyph, two concepts), `🤖` (Agents `:111`),
`🔌` (MCP `:239`), `📁` (Assets `:361`, Projects), `🔍`, `&#128736;` (Workflows).
Icon components: `ThemeIcon + IconFolder` (Repositories `:203`), `ThemeIcon + IconLink` (Integrations `:420`).

Emoji render per-OS, ignore theme colour, and are not `aria-hidden`.

**Change:** one `EmptyState({ icon, title, body, action })` using Tabler icons in a `ThemeIcon`.
Repositories/Integrations already show the target.

### 1.11 Terminology drifts between nav, page, and model

| Sidebar | Page title | Button | Model |
| --- | --- | --- | --- |
| Wrappers | Tools | "Add wrapper" | `Tool` |
| Connectors | MCP Servers | "Browse connectors" / "Add manually" | `MCPServer` |
| Secrets & Variables | Config Items | "Add Config Item" | `ConfigItem` |

Worse, **"session" means three different things**: a workflow step (workflow cards render
`{stepsCount} sessions`, `WorkflowsPage.tsx:396`), a terminal session, and a Builder session.

**Change:** a naming decision doc, then one pass. Nav label must equal page title must equal button
noun. The tri-meaning "session" is the one that actively misleads.

### 1.12 Accessibility

- **Click-only cards.** `<Box onClick>` / `<Card onClick>` with no `role`, `tabIndex`, or key handler:
  Onboarding agent cards (`OnboardingPage.tsx:300`, `:650`), Board preset picker (`BoardPage.tsx:3652`),
  Assets dropzone (`AssetsContent.tsx:572`).
- **Row-click navigation.** `SessionsPage.tsx:291` and `WorkflowRunsPage.tsx:186` navigate on
  `<Table.Tr onClick>`. Keyboard users can only reach the 16px external-link icon, whose accessible
  name comes from a Tooltip.
- **`aria-current` never set.** `SidebarNav` reads `window.location.pathname` at render time
  (`AppSidebar.tsx:371`). Under persistent layouts this is not reactive — the active state can lag
  a navigation and no `aria-current` is emitted at all.
- **Hover/focus done in JS.** `onFocus`/`onBlur` mutating `borderColor` (`WorkflowsPage.tsx:287`),
  `onMouseEnter/Leave` mutating `background` (`AppSidebar.tsx:352`, `BoardPage.tsx:3660`).
  No `:focus-visible` — keyboard users get no focus affordance on these controls.
- **Colour-only meaning** in chart legends and Overview activity dots (`OverviewPage.tsx:71-85`).

**Change:** an `ActionCard` primitive (button semantics + keyboard + focus ring); move all
hover/focus to CSS; make the sidebar active state derive from Inertia's `usePage().url`.

### 1.13 Liveness is invisible and inconsistent

Overview silently polls every 60s (`OverviewPage.tsx:258`), Runs polls every 10s while active
(`WorkflowRunsPage.tsx:80`), Sessions uses ActionCable, resource pages never refresh. Nothing on
screen tells the user which of these they are looking at.

**Change:** one `LiveIndicator` ("Live" dot / "Updated 2 min ago" + manual refresh) in `PageHeader`,
driven by whichever mechanism the page uses.

## 2. Screen-by-screen

### Auth & entry

**Login** (`pages/Auth/LoginPage.tsx`)
- `:79` hardcodes `<Logo colorScheme="dark" />`. `Logo` applies `brightness(0) invert(1)` for dark
  → **a white logo on a white card in light theme.** Drop the prop; the component already
  resolves the scheme itself (`Logo.tsx:12`).
- No "Forgot password", no self-serve sign-up. A visitor without an invite link is at a dead end
  with no explanation.
- Order reads wrong: Google button → `OR` divider → "Enter your credentials to access your
  workspace" → email form. The sentence sits *below* the divider, so it visually annexes the
  divider to Google. Move the sentence above the Google button or delete it.
- Footer "AI Agent Orchestration Platform" contradicts the "Aixle **Flow**" wordmark directly above.

**Invitations** (`pages/Invitations/Show.tsx`) — the best-composed screen in the app. Five variants,
each with a single clear action, correct copy. Only nit: `Logo` here (correctly) omits `colorScheme`
while Login forces it — same component, two behaviours.

**Onboarding** (`pages/Onboarding/OnboardingPage.tsx`)
- Progress is encoded **twice** — a `<Progress>` bar and a `<Stepper>` (`:579`, `:587`). Drop the bar.
- The viewer path auto-advances through two hidden server states (`:521`), so a viewer watches the
  bar jump 0 → 100 with no intermediate. Give viewers an honest 2-step stepper.
- Step 3 puts a 280px agent list + a 500px-min terminal iframe inside a `narrow` (800px) shell —
  ~500px of usable terminal. Auth terminals need width. Use the full shell for this step.
- Agent brand colours are hardcoded here (`:73`), again in `Profile/Show.tsx:65`, and expressed as
  *Mantine colour names* in `SessionsPage.tsx:44` — three sources, two of which disagree.
- Confetti correctly honours `prefers-reduced-motion` in CSS (`:103`). Good; keep it.

### Company scope

**Projects index** (`pages/Projects/IndexPage.tsx`)
- Search + sort are component state only — a filtered/sorted view cannot be linked or survive
  a reload. Push to the URL like Sessions/Runs already do.
- The Select at `:101` has no label and no "Sort:" prefix — it reads as an unexplained dropdown.
- `AVATAR_COLORS[project.id % 12]` (`ProjectCard.tsx:71`) assigns colour by id modulo. Colour carries
  no meaning, collides between projects, and the initial already identifies the project. Either make
  it a deterministic hash of the *name* or drop colour entirely.

**Workflow Catalog** (`pages/Company/WorkflowCatalog/IndexPage.tsx`) — clean. Missing: which project
already has a copy, and any indication of what the workflow *does* beyond a 3-line description.

**Company Members / Assets / Sessions** — all three lack `<Head title>`. Company Members offers role
changes only as menu items ("Make Admin" / "Make Employee"), so an employee can never be demoted to
**viewer** even though `viewer` is one of the three filter options on the same screen. Replace the
two menu items with a role `Select` in the row.

### Project scope

**Overview** (`pages/Projects/Overview/OverviewPage.tsx`)
- The entire stylesheet is an inline `CSSProperties` map (`:94-245`). Extract to a module.
- Board-distribution "Total" cell uses `--mantine-color-brand-7` + hardcoded `color: white`
  (`:228-244`) while siblings use `--app-bg-elevated` — the total reads as a button.
- 60s poll with no timestamp (see §1.13).
- 13 hardcoded activity-event hexes (`:71-85`).

**Tasks / Board** (`pages/Projects/Board/BoardPage.tsx`) — **5075 lines, 183 inline style objects**,
`window.confirm` for column delete (`:4385`), preset cards with JS hover transforms (`:3660`).
This file is past the point where it can be reviewed or restyled. Split into
`BoardPage` / `TaskCard` / `TaskDetailSidebar` / `BoardSettings` / `ActivityFeed` before any visual work.
The preset picker itself (`:3622`) is a genuinely good empty state — worth generalising.

**Workflows** (`pages/Projects/Workflows/WorkflowsPage.tsx`)
- `:407` renders the literal string **`0 runs` on every card**, regardless of actual run count.
  This is a factual falsehood on the primary list screen.
- Fixed 2-column grid; raw `<input>` with JS focus handlers next to Mantine inputs elsewhere;
  primary CTA is a raw `<button>` bypassing the `Button` component (`:292-324`).
- "Run History" and "Catalog" sit as equal-weight secondary buttons — one is a view of this page's
  data, the other leaves the project. Different weights.

**Builder** (`pages/Projects/Workflows/BuilderPage.tsx`) — three-pane, no responsive fallback.
`readOnly` is threaded through but the panes still render editable-looking controls; a read-only
visitor discovers the state by clicking.

**Workflow Runs list** — filters by state only. No filter by workflow and **no cost column**, though
cost is the number this audience watches. No live indicator despite a 10s poll.

**Sessions list** — 11 columns at `minWidth={900}`. The Models cell holds N wrapping badges, which
breaks row rhythm. Cost is colour-coded green/yellow/red at hardcoded ≤$1 / ≤$5 thresholds
(`:79-84`) with nothing on screen explaining the scale.

**New Session** — correctly narrow (720px) and delegated to a shared form. Good.

**Agents / Wrappers / Skills / Connectors / Assets** (`shared/resources/*`) — the most consistent
family, and the one worth standardising *on*. Three list shapes still coexist inside one nav group:
tables (Agents, Tools, MCP, Assets), a card grid (Skills), sectioned cards (Repositories, Integrations).
Pick one shape per "kind of thing" and state the rule.

**Connectors** specifically (`McpServersContent.tsx`) — the strongest screen in the product:
tool-drift alert with a reason the user can act on, per-row health glyphs, OAuth connect inline with
a real loading state. One defect: `kindFilter` defaults to `'custom'` (`:117`), so System servers are
hidden on first paint and the empty state claims **"No MCP servers configured"** when servers exist.
Default to `'all'`, or make the empty copy filter-aware.

**Secrets & Variables** (`ConfigItemsContent.tsx`) — highest consequence, weakest affordances:
native `confirm()` delete (`:63`), no reveal-once, no "last rotated", no "used by which workflow/tool".
A user cannot answer "is this safe to delete?" from this screen.

**Repositories / Integrations** — the This-Project / Company-wide split is the clearest scope model
in the app. Reuse that pattern for Agents, Tools and Assets, which currently express scope as a
`Badge` in a table cell.

**Members (project)** — native `confirm()`; the add-member `Select` collapses a person into
`"Name (email)"` with no avatar or role.

**Analytics (project)** — the only screen using `<Deferred>` + skeletons correctly; treat it as the
reference for loading. But: 12 stat tiles and 10 charts with no export, and a hand-rolled fixed-px
grid table (`:752`) that clips below ~1400px.

**Settings** — well structured. Its inline Members list duplicates the Members page and does not
link to it.

**Aixle Builder landing** — a marketing-shaped hero card inside the app shell. Also the only place
using `color="blue"` for a primary ThemeIcon, which is not a brand colour.

### Personal

**Profile** (`pages/Profile/Show.tsx`) — 1184 lines, six stacked cards in a 600px column.
- The Account/Usage `Tabs` is a **fake tab**: `onChange` calls `router.visit` (`:1105`), so the
  indicator never moves, and Back is a full page load. Make them real routes rendered as links,
  or make Usage a real tab panel.
- The MCP token is displayed once, "copy it now, it will not be shown again" (`:1002`) — in a plain
  `Code block` **with no copy button**. The one string in the app that must be copied is the one
  the app makes hardest to copy.
- Six cards, no sub-navigation. At this length it wants a left rail: Account / Companies / Agents / MCP.

**Usage** — same Material chart palette; otherwise consistent with Analytics.

### Docs

`pages/Docs/*` is a separate design language — its own 1181-line stylesheet, nav bar, search modal,
sidebar, TOC and breadcrumbs. It is also the only surface in the product with search and breadcrumbs.
Decide deliberately: either it is a marketing-adjacent surface (fine, document the split), or its
breadcrumb + search patterns should be promoted into the app shell — where they are missing.

## 3. Recommended sequence

**Phase 1 — stop the drift (small, high leverage)**
1. `PageHeader` (title + subtitle + actions + `<Head>` + breadcrumbs) → migrate all 38 screens.
2. `StatusBadge` with one state table → delete six `STATE_CONFIG` maps.
3. `EmptyState` with Tabler icons → delete every emoji-as-icon.
4. `useConfirm()` → delete five native `confirm()` calls.
5. Fix `Logo colorScheme="dark"` on Login; rebuild the sidebar AI banner on tokens.
6. Fix the hardcoded `0 runs` string.

**Phase 2 — one visual language**
7. Brand chart palette; replace the Material hexes in four screens.
8. Hex-literal lint rule for `pages/` + `shared/` TSX, with a shrinking allowlist.
9. Extract `OverviewPage`'s inline style map and `WorkflowsPage`'s `<style>` block into modules.
10. Terminology pass: nav label = page title = button noun; resolve the tri-meaning "session".

**Phase 3 — structure**
11. Responsive decision (§1.6), then execute it consistently.
12. `ActionCard` primitive; CSS-only hover/focus; sidebar active state from `usePage().url`.
13. Split `BoardPage.tsx`.
14. Profile sub-navigation; real Account/Usage routing; copy button on the MCP token.
15. Secrets screen: reveal-once, last-rotated, used-by, type-to-confirm delete.

## 4. What is already right

Worth protecting during any refactor:

- The `--app-*` token contract and its light/dark mappings (`mantineTheme.ts`) — the design system
  exists; it is under-used, not wrong.
- The Connectors screen's drift alert: it states the risk in the user's terms ("tool descriptions are
  instructions the agent reads") and offers the action next to it.
- The Invitations screen's five-variant handling.
- `Deferred` + skeletons on Project Analytics.
- The This-Project / Company-wide sectioning on Repositories and Integrations.
- The Board preset picker as an empty state that teaches rather than apologises.
- Copy quality throughout is above average — the problem is presentation, not writing.
