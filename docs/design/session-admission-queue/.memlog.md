Official PostgreSQL locking, Kubernetes quota/ConfigMap, Temporal message/error/versioning/client docs consulted.
- (assumption) A full developer draft was requested; ENV SESSION_CONCURRENCY_LIMIT is an installation-wide pool in v1. Separate per-company settings in a shared installation require an explicit choice; no reply to the optional clarification had arrived at this stage.
- (constraint) App namespaces use project first, otherwise global user id, with runtime origin prefix. NamespaceResourceQuota max_pods is 100 by default but CPU 4000m/memory 8Gi are often tighter; prod Pod limit is 3Gi (effective 2 homogeneous agent Pods), staging 2Gi (effective 4). Limits apply to spec resources, not measured usage.
- (decision) Choose PostgreSQL admission pool row lock plus durable per-session admission/permit and embedded launch outbox; Temporal performs lifecycle, existing schedule pattern recovers missed dispatch. Avoid Redis semaphore, worker concurrency knobs, or a dedicated queue service.
- (decision) One applicable pool per session: installation if configured, otherwise Project if present else User. One slot per supported TerminalSession (agent_session, workflow_step, auth_setup); standalone tool executions excluded explicitly. Slots count reservations through confirmed resource deletion independently of terminal_sessions.state.
- (decision) All reservation/cancellation/release mutations serialize pool then admission then session in short DB transactions; immutable ticket orders queued admissions FIFO, launch I/O after commit. Unreleased admitted rows are count source; no mutable cached occupancy counter initially. Release never based on TTL, failed state, or DELETE accepted.
- (decision) Durable creation intent and immutable admission token guard late workers. Stable namespace/name plus UID/admission labels make create retries idempotent. Ambiguous in-flight create and unavailable runtime retain the reservation until outcome/quiescence is established; no claim of a DB token atomically fencing Kubernetes.
- (decision) Queue waiting starts no container workflow, uses queued_at; started_at begins provisioning. Add queue-aware lifecycle/UI/cancellation and migrate workflow run watchdogs/timers. Step launch activity reuses session under step_run lock for retry idempotency.
- (decision) Remove old managed namespace ResourceQuota after new queue gate and resource limits migration audit; keep Pod requests/limits and namespace isolation. Existing quotas need explicit managed-only cleanup; ensure returning early does not delete them. Runtime quota/RBAC error classification and Pending polling must change.
- (decision) Enqueue/release invokes drain plus best-effort launch relay after commit; a registered minutely Temporal schedule repairs missed drains/launches and reconciles permits. Use stable agent-session id and explicit reject-duplicate/run lookup semantics; never replay agent exec solely to recover launch.
- (question) Before implementation settle installation-vs-company scope, auth_setup inclusion/priority, fallback defaults from audited effective caps and optional queue retention policy; draft fixes recommended values/behavior and labels choices.
- (decision) Roll out v2 container workflow separately for history compatibility, use deployment admission pause and drain legacy executions before cutover; sync authoritative DB policy once from ENV, never overwrite it on each worker boot. Normal cap decrease stops new grants without killing current runs.
- (decision) Review fixes applied: policy SHARE / writer UPDATE serializes revision and all limit changes; pool.limit is a cache refreshed before grant. Global immutable queue ticket sequence prevents pool-remap collisions.
- (decision) WorkflowRun stop marker under shared lock order gates enqueue/grant/relay/runtime operations; cancellation fanout durable and recoverable. Runtime operations ledger covers every Pod/Docker/Service/IngressRoute/Middleware create/start, not only first Pod.
- (decision) Capacity-wait states explicitly excluded from ordinary 30-minute running reaper; quota deletion uses namespace ownership plus audited exact quota UID allowlist since existing quota objects lack labels.
- (decision) Proposed queued workflow-step cancellation cancels parent run, marks StepRun cancelled and never invokes automatic on_failure retry; UI explicitly labels whole-workflow cancellation.
