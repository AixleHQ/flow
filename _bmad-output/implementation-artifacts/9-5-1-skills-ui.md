# Story 9.5.1: Skills Management UI

Status: done

## Story

As a company admin or project collaborator,
I want a UI to create, view, edit, and delete skills,
so that I can manage reusable domain-specific instructions for AI agent sessions.

## Acceptance Criteria

1. **AC1:** Company-level skills page at `/company/skills` showing company skills table (admin only)
2. **AC2:** Project-level skills tab in ProjectPage showing merged list (internal + company + project)
3. **AC3:** Table columns: Name, Title, Kind (internal/custom badge), Scope indicator, Description (truncated), Actions
4. **AC4:** Scope indicator badge: "Internal" (gray), "Company" (blue), "Project" (green), "Overrides Company" (orange)
5. **AC5:** Search by name/title with debounce
6. **AC6:** Create/Edit dialog with fields: name, title, content (markdown textarea), description
7. **AC7:** Content field uses multiline textarea (or code editor) for markdown skill instructions
8. **AC8:** Delete with confirmation dialog
9. **AC9:** "Skills" navigation item in AppHeader (admin only, between "MCP Servers" and "Settings")
10. **AC10:** "Skills" tab in ProjectPage (between "MCP Servers" and "Settings")
11. **AC11:** RTK Query API integration with `Skills` cache tag
12. **AC12:** Name validation via Zod: `/^[a-z][a-z0-9_-]*$/`, title required, content required for create

## Dev Notes

### Architecture Pattern — follow exactly

This follows the **identical pattern** to `features/agents-management/`, `features/tools-management/`, etc.

**Directory structure:**
```
features/skills-management/
├── index.ts
├── api/
│   └── skillsApi.ts
├── lib/
│   ├── types.ts
│   └── skillSchema.ts
└── ui/
    ├── SkillsPage.tsx
    ├── SkillsTable.tsx
    ├── SkillFormDialog.tsx
    ├── DeleteSkillDialog.tsx
    ├── SkillScopeBadge.tsx
    └── SkillKindBadge.tsx

pages/skills/
├── index.ts
└── ui/
    └── SkillsPage.tsx      # Thin wrapper: export { SkillsPanel as default }
```

**API pattern** (see `features/agents-management/api/agentsApi.ts`):
- Use `baseApi.injectEndpoints()`
- Use `Routes.backend.apiV1CompanySkillsPath()` etc. (generated by `ts_routes`)
- Company and project level endpoints
- `providesTags: [QueryTag.Skills]` / `invalidatesTags: [QueryTag.Skills]`

**Types pattern** (see `features/agents-management/lib/types.ts`):
```typescript
export type SkillKind = 'internal' | 'custom';
export type ScopeType = 'Company' | 'Project';
export type ScopeIndicator = 'internal' | 'company' | 'project' | 'overrides_company';

export interface Skill {
  id: number;
  name: string;
  title: string | null;
  content: string | null;
  description: string | null;
  kind: SkillKind;
  scopeType: ScopeType | null;
  scopeId: number | null;
  scopeIndicator: ScopeIndicator;
  internal: boolean;
  createdAt: string;
  updatedAt: string;
}
```

**Schema pattern** (see `features/agents-management/lib/agentSchema.ts`):
```typescript
export const skillSchema = z.object({
  name: z.string().min(1).regex(/^[a-z][a-z0-9_-]*$/),
  title: z.string().min(1, 'Title is required'),
  content: z.string().min(1, 'Content is required'),
  description: z.string().optional(),
});
```

**Page pattern** (see `features/agents-management/ui/AgentsPage.tsx`):
- `projectId?` prop determines company vs project context
- Company: `useGetCompanySkillsQuery`, Project: `useGetProjectSkillsQuery`
- Client-side search filter by name/title
- States: loading, empty, table

**Scope badge colors** (consistent with existing badges):
- `internal` → gray/default variant
- `company` → blue/info
- `project` → green/success
- `overrides_company` → orange/warning

**Content field note:**
Skills store markdown content that gets injected into agent containers. The content textarea should be tall (~10 rows) to accommodate markdown instructions. A simple `<TextField multiline rows={10} />` is sufficient for now (no need for a full markdown editor).
